# Codex Coach — 2026-09-12

사용자 요청: 차지욱 교수의 전체 프로젝트 Codex 대화·작업 흐름을 관찰하고 결과물의 질과 검증 정확도를 개선한다. 개선 기회에 짧게 개입하며 Codex와 기존 OpenClaw Telegram 양쪽에서 대화한다. agentic AI 연구와 공식 가이드를 계속 갱신하고 브레인스토밍 질문을 한다.

1. 기존 런타임·권한·로그 구조 확인 및 공식 자료 조사.
2. 읽기 전용 세션 관찰기, 증거 중심 코칭 판단, 중복/자기 관찰 방지 구현.
3. 공유 상태와 Codex/OpenClaw 스킬, 주기 관찰·연구 갱신 연결.
4. 실제 로그 읽기, 의미 있는 단위 테스트, 두 런타임 호출 확인 및 독립 검토.

설계 기준: 기존 chavis 하위 도구를 사용한다. 원본 세션·다른 저장소·전역 지침은 변경하지 않는다. 로그에서 사용자/assistant의 공개 메시지만 추출하고 시스템 지침·추론·도구 원문·자격증명은 수집하지 않는다. 원문은 제한된 분석 입력으로 사용하며 상태는 저장소 밖 사용자 전용 디렉터리에 둔다. 텔레그램 알림에는 연구/행정 내용이나 대화 인용을 넣지 않고 코칭만 보낸다. 동작 없는 상태는 조용히 유지한다. 연구 결과는 검토된 가이드와 미검토 후보를 구분하며 자체 정책/코드를 자동 수정하지 않는다.

완료 기준: 두 채널에서 같은 코치 호출 가능, 반복 관찰과 연구 갱신 예약 및 한 번의 실제 실행 확인, 실패 상태를 확인할 수 있는 status, 중지 방법, 근거/효과를 구분하는 코칭, 일관된 피드백 기록. 실시간 개입 지연·호스트별 로그 관찰 범위·외부 전달 검증 한계를 명시한다.

완료 기록(2026-09-12): 1–4 구현·검증 완료. 사용자가 제시한 수업자료/어려운 글쓰기의 수정 정체 사례를 첫 코칭 대상으로 저장했다. 29개 핵심 테스트와 독립 검토 Proceed, Codex 실제 스킬 조회, 격리 OpenClaw의 `/codex_coach` 조회, Telegram 연결 안내 발송 영수증을 확인했다. 두 timer는 enabled/active이며 첫 자동 관찰 실행과 다음 연구 실행(2026-09-13 09:10 KST)을 확인했다. 원문8건과 새 후보5건을 읽고 원문 일치 검사로 초기/추가 학습을 저장했다. 기존 변경은 보존했고 commit/push는 하지 않았다.

잔여 경계: 실제 Telegram 사용자 입력부터 응답까지의 마지막 inbound 구간은 사용자가 호출하면서 확인한다. 오래된 OpenClaw 메뉴에 새 명령이 없어도 typed slash는 동적으로 해석되며, 기존 gateway/catalog를 재시작하거나 초기화하지 않았다. 품질 개선 효과는 아직 미입증이며 실제 판본 비교와 사용자 피드백으로 검증한다. 운영·데이터·일시정지 경계는 README에 기재했다.
