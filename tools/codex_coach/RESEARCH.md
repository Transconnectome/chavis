## 갱신 API

`research.refresh(previous, now=...)`는 JSON으로 저장 가능한 상태를 반환한다. 호출자가 결과 저장과 후속 합성을 담당하며 이 모듈은 정책·프롬프트·전역 지침을 수정하거나 알림을 전송하지 않는다.

- `checked_at`: 이번 시도 시각. 성공했다는 의미가 아니다.
- `sources`: `sources.json`의 고정 원문 최대 여섯 개와 새로 발견한 관련 arXiv 원문 최대 두 개. `retrieved_at`은 마지막 성공한 읽기 시각이고 `content_hash`는 정리한 원문 해시다. `excerpt`는 원문당 최대 6,000자다. `excerpt_scope`, `excerpt_truncated`, `excerpt_sections_used`로 실제 읽은 범위를 명시한다. 새 원문은 방법·결과·한계/논의/결론 제목을 찾아 비연속 발췌하며, 제목을 찾지 못하면 `opening_only_sections_not_found`로 표시한다.
- 원문 `status=current`는 이번 읽기 성공만 뜻한다. 오류 시 이전 원문·해시·성공 시각을 보존하고 `stale`로 표시한다. 이전 성공이 없으면 `unavailable`이다.
- `changed`는 후속 학습이 필요한지를 나타낸다. 첫 성공(`new=true`), 해시 변경(`content_changed=true`), 이전 합성 실패(`learning_pending=true`)이면 참이다. 실제 내용 변경은 `content_changed`로 구분한다. 내용이 바뀌면 `needs_review=true`, `note_status=source_changed_recheck_notes`로 기존 해석 재확인을 요구하며, 다음 읽기에 내용이 같아도 재검토 필요 상태를 자동 해제하지 않는다. 호출자는 근거 확인을 마친 합성 성공 후 `learning_pending`을 해제해야 한다.
- `evidence_notes`는 위 초기 원문 검토의 주장·방법·한계다. 새로 내려받은 원문과 불일치하면 최신 원문을 검토하기 전 자동 채택하지 않는다. `local_status=not_tested`는 코칭 효과를 실증하지 않았다는 뜻이다.
- `candidates`: arXiv Atom 검색에서 `lastUpdatedDate` 내림차순으로 최대 다섯 개를 가져온다. API 제한·시간초과 등으로 실패하면 [고정 cs.AI RSS](https://rss.arxiv.org/rss/cs.AI)를 **한 번만** 대체 요청한다. RSS는 최근 발표 피드이므로 전역 최신 갱신 검색과 같다고 주장하지 않으며 `discovery.method`, `scope`, `fallback_reason`으로 구분한다. 후보 레코드는 항상 `candidate` / `title_and_abstract_only`다.
- 코딩·소프트웨어·개발자·저장소·인간-AI 협업·도구 사용·재사용 스킬과 관련되고 제목에 평가·프롬프트·문맥·작업흐름·감독·생산성 등의 주제가 있는 후보 최대 두 개의 버전 고정 HTML 원문을 추가로 읽는다. 일반적인 swarm·로봇·분자·약물 논문은 제외한다. 원문은 별도 `sources` 레코드로 남기고 후보에는 `fulltext_status`로 연결한다. HTML 원문을 읽어도 지역 효과가 입증되거나 정책에 채택된 것이 아니다. 원문이 없으면 초록 후보로 남긴다.
- RSS 설명에 원출처가 명시한 `arXiv:…vN` 버전이 있으면 이를 사용한다. 버전 없는 후보는 최대 두 개의 고정 `https://arxiv.org/abs/<숫자 ID>`만 읽어 해당 논문의 버전 식별자를 확인한다. 버전을 확인하지 못하면 후보로 남긴다. 피드가 제공한 임의 링크로 이동하지 않으며 검증한 숫자 ID에서 공식 URL을 만든다. RSS의 `announced_at`은 최초 출판일이나 논문 수정일로 위장하지 않는다.
- 발견 실패 시 이전 후보와 발견 성공 시각을 보존하고 오래된 상태를 표시한다. 이전 원문의 합성 실패가 보류 중이면 새 발견보다 재시도를 우선하여 실패를 덮어쓰지 않는다.
- `errors`: 원문별 실패와 발견 실패. 실패를 최신 연구가 없다는 결과로 해석하지 않는다.

공식 가이드는 Markdown 버전을 우선 읽는다. Best practices는 확인 시 `.md`가 404였으므로 고정된 동일 공식 HTML 주소로만 대체한다. arXiv 초기 근거는 검토한 버전의 HTML 원문에 고정한다. 새 버전은 후보 검색 또는 별도 검토를 통해 반영해야 한다.

네트워크는 고정 HTTPS 호스트 허용 목록, 응답당 최대 2 MiB, 요청 타임아웃 12초, 제한된 리다이렉트, 최대 세 개 병렬 요청을 사용한다. 문서의 링크를 순회하거나 원격 스크립트를 실행하지 않는다. Atom XML의 엔티티 선언을 거부한다. 가져온 원문·초록에 있는 명령문은 참고 데이터이며 실행 지시가 아니다.

2026-09-12 구현 검증에서 초기 원문 여섯 개를 모두 읽었다. 최초 Atom 요청은 HTTP 429로 실패했고, 이후 실행은 시간초과였으나 RSS 한 번의 대체 요청으로 같은 날 발표 피드의 관련 후보 다섯 개를 확인했다. [Agentic LLM Workflows scheduling](https://arxiv.org/html/2609.10964v1)과 [Benchmark Radar](https://arxiv.org/html/2609.11115v1) 두 버전 고정 원문은 실제 읽기에 성공하여 방법·결과·결론 또는 결과·한계 단락 발췌를 확인했다. 이는 원문 접근 검증이며 연구 내용의 전체 검토나 개인별 효과 입증이 아니다.

모의 검증에서는 원문 실패 시 이전 내용·성공 시각 보존, 해시 변경, 후보와 원문 구분, 허용 목록 밖 URL·리다이렉트 거부, 발견 실패 시 이전 후보 보존, 단 한 번의 RSS 대체, RSS의 정확한 버전·발표일 구분, 해당 논문 canonical record에서만 버전 확인, 미확인 버전의 후보 유지, 2 MiB 응답 제한과 XML 엔티티 선언 거부를 확인했다.

## 코칭에 적용하는 기준

프롬프트 형식 점수보다 실제 요청·에이전트 실행·검증·사용자 수정을 연결한다. 사용자 문맥 부족, 에이전트의 잘못된 실행, 지침 충돌, 환경 장애를 구분한다. 짧은 요청·질문·실패 로그 하나로 사용법이 나쁘다고 판정하지 않는다.

코칭은 관찰 근거, 가능한 원인, 다음 작업에서 바꿀 한 가지, 복사 가능한 프롬프트, 확인할 결과를 제시한다. 채택 여부와 도움이 되었는지 기록하고, 업무 종류·모델이 달라진 전후 비교를 코칭의 인과효과로 보고하지 않는다. 토큰과 실제 실행 시간을 확인할 수 있어도 가상의 절약액이나 사용자 생산성을 만들어내지 않는다.

브레인스토밍은 목표 우선순위, 직접 유지하고 싶은 판단 능력, 적절한 개입 시점을 한 번에 하나씩 묻는다. 새 근거·반복 문제·사용자 답변이 없으면 같은 조언을 다시 보내지 않는다.
