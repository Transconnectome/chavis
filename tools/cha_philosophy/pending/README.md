# Gmail 스레드 문맥 수정안 — 운영 반영 전

`thread-context.patch`는 이 디렉터리의 상위 운영 코드에 적용할 추가 수정안이다. 현재 기본 명령과 timer는 824개 검사를 통과한 운영 코드를 사용한다. 이 패치를 자동으로 적용하는 설치 동작은 없다.

패치를 적용한 별도 사본은 2026-09-13 전체 883개 검사를 통과했다. 2026-09-14 인계에서 깨끗한 운영 코드 사본에 패치를 적용하여 모든 Python 해시가 그 검사 사본과 일치함을 확인했다. 인계 중 운영 버전의 824개 검사도 다시 통과했다. 패치에는 비공개 원문·DB·검토 결과가 없다.

## 포함된 변경

- Gmail 전체 스레드의 원자적 저장·목록 검사와 별도의 원격 확인 시각.
- 다른 직접 발언·후속 정정의 순서를 보존한 제한된 추출 문맥. 다른 사람이나 범위 밖 발언을 교수 직접 근거로 승격하지 않는다.
- 스레드 구성·내용·제외 상태 변경에 따른 후보 재추출과 기존 원칙의 무효화.
- 자동 의존성 연결과 실제 검토 표시의 분리. 명시적으로 검토한 현재 revision만 활성화할 수 있다.
- 개인 전용 편집 링크의 좁은 가림과 관련 합성 회귀 검사.
- `thread` 조회, 명시적 context revision 검토 옵션과 사용 설명.

실제 TLS handshake timeout을 재시도하는 후속 수정은 포함되지 않았다. 일반 연결 시간 초과의 기존 한 차례 재시도만 유지된다.

## 적용 전에 확인할 것

기존 Gmail 근거 원칙에는 새 스레드 검토 표시가 없다. **운영 코드만 바꾸면 해당 원칙의 재사용이 보류된다.** 최신 원문과 스레드 구성을 읽고 검토한 뒤, 정확한 revision 연결과 코드 반영을 함께 준비해야 한다. 자동으로 기존 원칙을 교수 확인 상태로 올리면 안 된다.

루트 HANDOFF에 비공개 검토 manifest, 별도 DB 검증, 좁은 가림 계획의 위치가 있다. 이는 과거 snapshot이므로 현재 DB와 다시 대조한다. 순수한 로컬 가림을 새 원격 조회로 기록하지 말고, 검증 시각·checkpoint·다른 작업의 변경을 보존한다. 검토되지 않은 새 메시지가 있으면 재검토한다.

독립된 작업 사본에서 다음 명령으로 패치를 먼저 확인할 수 있다.

```bash
git apply --check tools/cha_philosophy/pending/thread-context.patch
git apply tools/cha_philosophy/pending/thread-context.patch
python3 -m pytest -q tools/cha_philosophy/tests
```

이 절차는 코드 적용·로컬 검사이며 운영 이관·모델 재시작·외부 자료 전송을 실행하지 않는다. patch 파일이 남아 있다는 이유만으로 현재 코드가 미적용 상태라고 추정하지 말고 적용 전후 diff와 해시를 확인한다.
