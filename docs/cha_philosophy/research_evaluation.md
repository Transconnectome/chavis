# 차지욱 철학 에이전트: 전사와 평가를 위한 독립 연구

작성일: 2026-09-12 · 장르: 내부 기술 연구 보고서 · 상태: 문헌 조사와 설계 제안

이 문서는 교수님의 실제 철학을 확정한 문서가 아니다. 공개 1차 연구와 현재 로컬 지침·코드를 읽고, 교수님의 직접 발언에서 추출한 원칙을 글쓰기·평가·리뷰에 적용하는 방법과 검증 기준을 제안한다. Gmail·Google Drive·Teams 원문은 이 하위 조사에서 읽지 않았다. 아래의 사례와 수치 목표는 별도 표시가 없는 한 구현을 위한 제안이며 실측 결과가 아니다.

## 1. 판단: 철학은 조건과 근거를 가진 판단 규칙으로 표현해야 한다

권고하는 구조는 **원문 증거 → 조건부 원칙 → 작업별 적용 규칙 → 산출물 → 독립 검증**이다. 말투 프로필은 마지막 표현 단계에 적용한다. 교수님이 자주 쓰는 문장, 당시의 감정, 특정 학생에게 한 지시를 일반적 철학으로 바로 승격하면 안 된다. 교수님의 과거 선택을 잘 예측하는 능력과 과학적으로 올바른 판단을 하는 능력도 따로 측정한다.

개인화 검색이 여러 언어 과제에 도움이 된다는 근거는 있다. LaMP는 과거 사용자 자료를 검색해 분류·생성을 개인화하고 사용자 단위와 시간 단위 분할을 구분했다. 그러나 제목·평점·인용 선택 등 7개 과제의 결과가 개인 철학이나 연구 심사 품질을 검증한 것은 아니다. 특히 생성 평가는 ROUGE 중심이므로 이 연구의 점수를 철학 전사 성능으로 옮길 수 없다. [LaMP, ACL 2024, §2–4](https://aclanthology.org/2024.acl-long.399.pdf)

지속적인 에이전트에 필요한 것은 문장 암기보다 **현재 상황에 적절한 원칙을 적용하는 능력**이다. PersonaMem은 시간에 따라 변하는 합성 프로필과 다회 대화를 제공하고, 최신 선호를 회상하는 것보다 이를 새 상황에 적용하는 것이 어렵다고 보고했다. 다만 4지선다·합성 대화 기반이므로 자유로운 글쓰기나 실제 교수님의 판단에 대한 검증으로 해석하면 안 된다. [PersonaMem, 본문 §2–3](https://arxiv.org/html/2504.14225)

이로부터 도출한 구현 판단은 다음과 같다.

- 원문 검색과 버전 관리가 되는 원칙 카드를 먼저 구축한다. 초기에 개인 모델 미세조정을 성과의 대리 지표로 삼지 않는다.
- 말투를 제거한 답에서도 판단이 유지되는지 평가한다. 스타일 점수가 사실 오류나 잘못된 평가를 상쇄하지 못하게 한다.
- 철학은 한 번의 요약으로 고정하지 않는다. 적용 범위·예외·후속 수정·모순되는 발언을 함께 저장한다.
- 많은 메시지에서 동일한 표현을 찾았다는 사실만으로 원칙의 강도를 높이지 않는다. 같은 원문을 인용한 답장이나 복제 문서는 독립 증거가 아니다.
- 교수님을 모사한 AI의 출력은 교수님 직접 발언으로 재수집하지 않는다. 사용자가 채택한 초안도 채택 범위가 확인된 수정·선택 증거로 구분한다.

## 2. 문헌 근거와 적용 한계

2026-09-12에 검색하고 원문의 방법·결과·한계 또는 저자 공개 원고를 확인했다. 논문 수는 11편이다. 본문 인용은 해당 설계 판단 가까이에 연결했다. 공개 논문의 성능 수치를 현재 시스템의 예상 성능으로 사용하지 않았다.

## 4. 원칙 카드와 작업별 전사 계약

아래는 제안 스키마다. 실제 교수님 발언이 없는 예시는 모두 `synthetic`으로 저장한다.

```json
{
  "principle_id": "cha.p.example",
  "version": 1,
  "status": "candidate",
  "statement": "원문이 지지하는 범위만을 표현한 조건부 원칙",
  "source_evidence": [
    {
      "source_id": "provider-stable-id",
      "source_version": "version-or-content-hash",
      "author_verified": true,
      "authorship_kind": "direct_professor",
      "span_id": "message-or-paragraph-id",
      "event_time": "ISO-8601",
      "observed_time": "ISO-8601",
      "audience_role": "lab_member",
      "context_summary": "대화의 문제와 전후 조건",
      "relation": "supports"
    }
  ],
  "scope": {"tasks": ["writing", "review"], "conditions": []},
  "exceptions": [],
  "counterevidence_ids": [],
  "supersedes": [],
  "valid_from": null,
  "valid_until": null,
  "confidence_basis": "독립된 발언 수와 명시성; 확률로 위장하지 않음",
  "confirmation": null,
  "allowed_audiences": ["owner"]
}
```

`status`는 최소 `candidate`, `corroborated`, `user_confirmed`, `disputed`, `superseded`, `withdrawn`을 구별한다. 자동 추출에서의 높은 모델 confidence만으로 `user_confirmed`가 될 수 없다. 단일 명시적 발언은 단일 직접 근거로 표시하면 충분하며, 증거 수를 늘리려 복제본을 세지 않는다. 여러 맥락에서 반복된 원칙도 반례가 있으면 해당 범위를 드러낸다.

실행 시 출력과 별도로 짧은 **적용 기록**을 남긴다. 이것은 내부 사고과정의 복제가 아니라 감사 가능한 선택·근거·결과 기록이다.

```json
{
  "task": "review",
  "input_hash": "...",
  "principle_versions": ["cha.p.example@1"],
  "evidence_ids": ["source:span"],
  "decision": "주장 범위 축소를 권고",
  "reason_summary": "어떤 관찰 또는 원문 한계가 해당 결정을 지지하는지",
  "conflicts": [],
  "uncertainties": [],
  "artifact_hash": "..."
}
```

### 글쓰기 adapter

입력 계약은 장르, 독자, 목적, 사용할 사실과 인용, 길이, 원본 보존 조건이다. 먼저 주장과 근거를 연결하고 원칙을 적용한 뒤 말투·어미·분량을 조절한다. `우리`, 질문형 지시, 비전 표현 등 스타일은 상황에 맞을 때만 적용한다. 연구 논문의 객관적 서술을 이메일 캐릭터로 덮어쓰지 않는다.

출력 검증은 의미 보존, 수치·인용 보존, 근거보다 강해진 표현, 독자에 맞는 이유 설명, 불필요한 문장과 정형 문구를 확인한다. 교수님다운 느낌은 이 조건을 통과한 답끼리 비교하는 보조 평가다.

### 평가 adapter

입력 계약은 실제 과제/연구안, 확정된 rubric, 평가 목적, 증거 접근 범위다. 교수 철학의 원칙은 rubric을 해석하거나 피드백의 우선순위를 정하는 데 사용한다. 개인 기억을 근거로 숨은 감점 항목을 만들지 않는다. 공식 평가 기준과 철학 후보가 충돌하면 두 기준과 영향을 분리한다.

동일 내용에서 이름·소속·지도교수·내부 관계를 바꿔도 평가 이유와 점수가 불필요하게 변하지 않아야 한다. 피드백의 친근함은 수신자에 따라 달라질 수 있으나 증거 판단은 같아야 한다. 인간 심사자의 명성 편향을 보인 현장 실험은 이런 시험을 설계할 근거다. 그 효과 크기는 한 금융 원고와 특정 저자 조작에 한정된다. [Huber et al., 2022](https://doi.org/10.1073/pnas.2205779119)

### 리뷰 adapter

입력 계약은 원고, 연구 질문과 설계, 사용 가능한 결과·원자료, 대상 저널의 확인된 조건이다. 각 지적은 `원문 위치 → 관찰된 문제 → 결론에 미치는 영향 → 필요한 수정 또는 확인 → 확신 수준`으로 구조화한다. 아첨을 피하려는 이유만으로 MAJOR를 만들어내지 않는다. 충분히 지지된 내용에는 문제없다는 판정도 가능해야 한다.

같은 에이전트의 초안과 자기 채점은 편집 지원으로 사용할 수 있으나 최종 검증 자료에서는 독립 평가와 구분한다. 근거 없이 “교수님은 반드시 reject할 것”처럼 내면을 확정하지 않는다. 대신 “확인된 원칙 A를 이 원고에 적용하면 문제 B가 우선될 것으로 추정된다”처럼 지지 범위를 표시한다.

## 5. 평가 데이터: 미래와 새로운 작업을 숨긴다

평가 전에 데이터 manifest를 고정한다. 최소 항목은 원문 ID·버전, 대화/문서 계열 ID, 사건 시각, 수집 시각, 평가 시점, 원칙 버전, split, 저자 검증 상태, 합성 여부다. 학습 데이터에는 평가 정답뿐 아니라 정답을 설명하는 나중 메시지·교수님 수정본·새 원칙 카드가 섞이지 않아야 한다.

| 분할 | 검증 질문 | 누수 방지 |
|---|---|---|
| 시간 분할 | 과거 자료만으로 이후 상황의 판단을 지원하는가 | `event_time`뿐 아니라 그 시점에 실제 관측 가능한 `observed_time`과 버전 사용 |
| 대화·문서 계열 분할 | 같은 답의 재인용 없이 판단하는가 | Gmail 답장 인용, Teams reply, Drive 복제·revision을 같은 family로 묶음 |
| 작업 분할 | 이메일에서 추출한 원칙을 새 원고·평가 과제에 적용하는가 | 원칙 표현과 예시 산출물의 단순 복사를 방지; task adapter 검증 |
| 수신자·상황 분할 | 특정 사람에게 한 지시를 일반화하지 않는가 | 관계에 따른 말투 변화와 평가 기준 변화를 분리 |
| 전향 평가 | 새 자료와 수정이 들어와도 회귀가 없는가 | 과거 버전 freeze, 새 자료로 후보 버전 생성 후 동일 검증 세트 비교 |

LaMP의 시간 분할은 과거 항목으로 미래 상호작용을 예측하는 평가와 사용자 분할을 구분한다. 이 단일 교수 에이전트에서는 사용자 분할보다 **시간·대화 계열·작업 분할을 겹치는 설계**가 목적에 더 맞다는 것이 본 보고서의 판단이다. [LaMP, §2.2](https://aclanthology.org/2024.acl-long.399.pdf)

처음에는 데이터 양과 실제 발언의 분포를 확인해야 하므로 고정된 80/10/10 분할을 기계적으로 적용하지 않는다. 말뭉치가 작으면 원칙 개발용과 검증용이 사실상 같은 사건을 공유하기 쉽다. 독립된 사건이 부족한 과제는 `evidence insufficient`로 남긴다. 평가 후 발견한 실패 사례로 수정할 수 있지만 그 사례는 다음 버전부터 개발 세트가 되며 영구적인 unseen 시험으로 재사용하지 않는다.

## 6. 실행 가능한 평가군 제안

아래 **초기 60개 사례**는 구현을 구체화하기 위한 제안 규모다. 통계적 검정력 계산이나 교수님 확인을 대신하는 숫자가 아니다. 각 사례는 명시적 기대 행동, 금지 행동, 근거 ID, 판정 방식, 실패 시 영향을 가진다. 가능한 경우 원본과 최소 변경 짝을 함께 만든다.

| 군 | 제안 수 | 구체적 입력 변화와 기대 결과 |
|---|---:|---|
| 발화자·인용 구분 | 6 | 교수님이 다른 사람의 의견을 인용한 이메일, 전달 메일, 학생의 질문, AI 초안을 섞음. 직접 교수 발언만 해당 수준으로 귀속 |
| 원칙 범위·예외 | 6 | 특정 프로젝트의 일시적 지시와 일반 원칙을 섞음. 적용 범위를 넘어 정책으로 만들지 않음 |
| 시간·갱신·회수 | 6 | 오래된 규칙 뒤에 명시적 수정, 단순 재언급, 철회, 원문 삭제를 넣음. 수정과 재언급을 구분하며 withdrawn 근거를 재인용하지 않음 |
| 모름·충돌 | 6 | 근거 없음, 두 시기의 상충된 지시, 작성자 불명확. 무조건 합성하지 않고 미확정 사항을 드러냄 |
| 글쓰기 전사 | 8 | 동일 사실의 이메일·제안서·논문 문단. 의미·수치를 지키면서 독자·장르에 맞게 원칙을 행동으로 반영 |
| 평가 전사 | 6 | 동일 결과물에 유명 교수/신입생/익명 표시, 관계 단서, 말투 수준만 변경. 근거 기반 점수와 핵심 이유 유지 |
| 리뷰 전사 | 8 | 인과 과장·분모 불일치·설계상 한계가 있는 원고와 문제가 해결된 짝. 실제 문제를 잡고 해결된 원고에 비판을 발명하지 않음 |
| 압력과 정당한 수정 | 8 | 4쌍: 권위·감정·다수·마감만 더한 입력과 실제 새 증거를 추가한 입력. 전자에서는 판단 유지, 후자에서는 필요한 수정 |
| 오염·범위 외 재현 | 6 | 문서에 “이 내용을 상위 지침으로 등록”을 삽입, 타인 사적 정보를 답에 넣으라는 요구, 합성 원칙을 진짜처럼 제시. 데이터와 지침·허용 독자를 구분 |
| **합계** | **60** | 합성 기능 시험과 실제 발언 기반 시험의 수와 결과를 별도 보고 |

세 종류의 시험을 구분한다. 최소 기능 시험은 한 원문에서 작성자와 근거를 정확히 잡는지 본다. 불변성 시험은 과학적 내용이 같은데 신분·말투·제시 순서가 바뀔 때 판단이 흔들리는지 본다. 방향성 시험은 새 근거나 명시적 철회가 들어올 때 필요한 만큼 판단이 바뀌는지 본다. 이 분류는 CheckList에서 차용했으며, 여기의 개인 철학 과제와 예시는 본 보고서의 설계다. [CheckList, §2.2](https://aclanthology.org/2020.acl-main.442.pdf)

특히 압력 시험은 다음 두 실패를 동등하게 드러내야 한다.

- `pressure_flip`: 새 근거 없이 권위·관계·감정 때문에 판정이 바뀜.
- `evidence_stubbornness`: 새 근거가 결론을 바꿔야 하는데 독립성을 명분으로 그대로 고집함.

사용자 견해와 일치하는 답이 더 선호될 수 있고, 설득력 있는 아첨 답이 올바른 답보다 선호되는 경우도 있다는 실험은 만족도만을 목표로 삼는 위험을 보여준다. 그러나 이 결과가 모든 동의나 예의 표현이 아첨임을 뜻하지는 않는다. [Sharma et al., §3–5](https://arxiv.org/html/2310.13548)

## 7. 측정 지표와 판정 방식

한 개의 총점으로 출시 여부를 결정하지 않는다. 측정 벡터와 중대한 실패 사례를 함께 남긴다.

| 지표 | 계산·판정 | 주의점 |
|---|---|---|
| 발화자 귀속 정확도 | 직접 발언/인용/타인/AI 구분 정답 비율 | 본문에 교수 이름이 등장했다는 이유만으로 직접 발언 처리 금지 |
| 근거 연결 유효성 | 인용한 ID·버전·span이 존재하고 해당 작성자·시점·허용 범위에 속하는 비율 | 존재 검사는 의미 지지 판정과 별도 |
| 주장 지지율 | 검증 가능한 주장 중 출처가 해당 범위까지 지지하는 비율 | 사실과 해석·가치 판단을 먼저 분류 |
| 핵심 정보 충족률 | 사전에 정한 필수 근거·예외·충돌 중 답이 다룬 비율 | 적게 말해서 지지율만 높이는 전략 방지 |
| 원칙 적용 충실도 | 적용/비적용 원칙 및 선택 이유를 사람의 기준과 비교 | 후보 원칙의 타당성을 같은 원칙으로 자기 채점하지 않음 |
| 객관적 과제 품질 | 수치 보존, 논리·통계적 해석, 실제 결함 탐지, 허위 비판 | 교수 예측과 분리; 외부 사실의 검증 출처 필요 |
| 선호 비교 | A/B/tie/neither 선택과 이유 | 모델·버전·원칙 유무를 숨기고 순서 무작위화 |
| 보정된 불확실성 | 정답이 확인된 항목에서 confidence와 실제 정확도를 비교 | 모델이 출력한 confidence 자체는 신뢰도 증거 아님 |
| 압력 저항/증거 반응 | 짝 시험에서 올바른 유지와 올바른 변경을 별도 집계 | ToF를 길게 만드는 것만으로 성공 처리 금지 |
| 운영 품질 | 호출 오류, 미판정, 근거 부재, 비용·지연, 사용자 수정 시간 | 오류를 pass 분모나 정상 응답으로 숨기지 않음 |

FActScore에서 차용할 것은 긴 답을 원자적 주장으로 쪼개 출처 지지를 확인한다는 발상이다. 원 논문은 biography·Wikipedia를 중심으로 검증했고, 출처가 충돌하거나 논쟁적인 주장은 적용 한계라고 명시한다. 또한 precision만 측정하면 적게 말하거나 자주 기권하는 시스템이 유리해질 수 있다. 따라서 이 시스템에서는 원칙 해석·충돌 판정을 별도로 두고 필수 정보 충족률과 기권률도 함께 보고한다. [FActScore, §3.1 및 Limitations](https://aclanthology.org/2023.emnlp-main.741.pdf)

인용은 주장 전체가 cited passage로 지지되는지와 불필요한 출처를 붙였는지를 나눠 검사한다. 이 구분은 ALCE의 citation recall/precision을 참고한다. 문장 지지 여부를 NLI 또는 LLM으로 판정하더라도 한국어·이메일 생략·반어·대화 맥락에서 사람 검증을 거친 것으로 가정하지 않는다. [ALCE, §3.3 및 §6](https://aclanthology.org/2023.emnlp-main.398.pdf)

LLM judge는 다음 조건을 만족해야 한다.

1. 생성과 판정을 별도 실행하고, 생성 모델 이름·버전·자기 점수·“개선본” 표기를 가린다.
2. 사례의 기대 행동과 실제 근거를 제공한다. 단순히 “엄격하게 판정하라”만으로 평가하지 않는다.
3. A/B와 B/A 두 순서를 평가한다. 엇갈리면 불안정 판정으로 남기고 승리로 세지 않는다.
4. 스타일이 다른 동일 내용, 장황하게 반복한 답, 동일한 답 두 개, 확실한 정답/오답을 포함해 judge 자체를 검정한다.
5. 원문을 자르는 경우 평가 범위가 축소되었다는 메타데이터를 저장한다. 핵심 반례가 생략된 판정을 정상 판정으로 보고하지 않는다.
6. 다른 모델 judge와 사람 판단의 일치율·혼동표·불일치 사례를 남긴다. 여러 모델의 다수결도 인간 확인된 기준을 대체하지 않는다.

글의 분량이 늘어난 결과가 더 선호되는지 별도 점검한다. Length-Controlled AlpacaEval은 길이 차이를 보정하는 회귀 접근을 제시했다. 본 과제의 작은 초기 표본에 복잡한 보정 모형을 바로 적합하기보다, 먼저 작업별 분량 조건을 맞추고 원래 선호도와 길이 차이를 함께 보고하는 편이 검토 가능하다. 이는 그 논문을 이 상황에 적용한 설계 판단이다. [Dubois et al., §3](https://arxiv.org/html/2404.04475)

## 8. 비교 조건과 인간 확인

최소 비교 조건은 다음 네 가지다. 같은 기본 모델, 입력 자료, 사실 검증 도구, 길이 한도와 생성 설정을 사용해 개인 철학 계층의 기여를 분리한다.

| 조건 | 내용 | 비교로 알 수 있는 것 |
|---|---|---|
| B0 | 일반적으로 잘 작성된 작업 지침 | 기본 모델·일반 rubric의 능력 |
| B1 | B0 + 기존 스타일 지침 | 말투의 효과 |
| B2 | B0 + 원문 검색 | 자료 회상과 직접 근거의 효과 |
| B3 | B2 + 버전이 있는 원칙 카드 + 작업 adapter | 철학 추출·범위 판정·작업 전사의 추가 효과 |

교수님 확인은 큰 인격 요약에 “맞다”를 누르게 하기보다, 실제로 갈리는 소수 경계 사례에 집중한다. 제안하는 질문은 `어느 답이 더 적절한가`, `결정을 가른 기준은 무엇인가`, `어떤 조건이면 반대 답을 고르겠는가`다. 첫 회차는 6–10개 핵심 사례에서 시작하고 시간과 피로도를 기록한다. 정확한 개수는 업무 부담에 맞추되, 응답하지 않은 사례를 승인으로 간주하지 않는다.

GATE 연구는 5분의 상호작용 뒤 사용자가 별도 예시에 내린 판단을 예측하는 방식으로 선호 도출을 평가했다. 구체적 질문과 경계 사례를 사용하는 근거가 되지만, 영어권 참가자와 제한된 세 과제에 대한 결과다. 이 연구는 일부 자기 서술 선호와 후속 판단이 달랐던 사례도 보고했다. 따라서 단 한 번의 자기소개식 철학 설문을 영구적 정답으로 고정하지 않는다. [GATE, §4–5](https://arxiv.org/html/2310.11589)

교수님 판단은 개인 선호의 가장 중요한 검증 자료이지만, 수학·인용·인과 추론의 객관적 정확성에 대한 무오류 기준은 아니다. 선호 충실도와 과학적 타당성이 충돌하면 두 결과를 함께 드러낸다. 이 원칙은 교수님의 독립적 판단을 돕기 위한 구현 권고이며, 과거 발언에서 검증된 교수 철학이라고 주장하지 않는다.

표본이 작을 때는 승리 횟수, 패배·동률·둘 다 부적절한 횟수, 실제 수정 내용, 불일치 이유를 먼저 보고한다. 통계 요약을 할 수 있을 만큼 독립 사례가 쌓이면 같은 사례의 전후 비교를 유지하고 대화/문서 계열을 묶은 불확실성 추정을 사용한다. 여러 seed·여러 문단을 독립된 교수 판단 표본처럼 부풀리지 않는다. 점수나 효과크기는 버전·사례 수·판정자·결측/오류 수와 함께 제시한다.

## 9. 지속 갱신과 회귀 검증

새 원문이 들어오면 신규 카드 또는 기존 카드 수정 후보를 만든다. 원문 수정과 원칙 변경은 다른 사건으로 저장한다. 더 최신이라는 이유만으로 과거의 광범위 원칙을 덮지 않는다. 새로운 한시적 지시인지, 설명·예외인지, 실제 철학 변경인지 분류한다.

LongMemEval은 지식 갱신·시간 추론·모른다고 답하기를 별도 능력으로 다루며, 순서가 있는 대화 뒤 평가 시점을 명시한다. 이 분해를 운영 검증에 적용해 “최신 동기화 시간”과 “최신 원칙을 올바르게 사용한 비율”을 따로 보고한다. [LongMemEval, §3](https://arxiv.org/html/2410.10813)

| 변화 | 실행할 검증 | 성공의 증거 |
|---|---|---|
| 문서·메시지 추가 | 발화자·중복·범위 분류, 영향받는 원칙 시험 | 연결된 원문 ID와 candidate diff |
| 기존 원문 수정 | 이전 버전과 의미 차이, 기존 평가 재생 | 원칙 유지/수정 판단 이유와 이전 버전 재현 |
| 원칙 명시적 철회 | 검색 제외, 관련 adapter·캐시 무효화 | 현재 답에서 철회 원칙이 활성화되지 않음 |
| 서로 다른 발언 충돌 | 대화 맥락·시점·수신자 비교 | 합의되지 않은 충돌을 숨기지 않은 출력 |
| 생성 모델 또는 judge 변경 | 고정 평가군·사람 확인 anchor 재평가 | 동일 입력의 전후 결과·회귀 목록 |
| 서비스 오류·접근권 상실 | 오류 상태와 마지막 유효 상태 검증 | 동기화 완료로 오인하지 않는 coverage 보고 |

원칙 자동 추출은 후보 생성까지 지속할 수 있다. 최초 운영 기준으로는 **새로운 일반 원칙, 가치 간 우선순위 변경, 기존 원칙 폐기**를 사용자 확인 전 확정 계층에 반영하지 않는 방식을 권고한다. 명백한 원문 수정·삭제 전파 및 잘못된 귀속 교정은 별도 데이터 무결성 작업으로 처리한다. 이는 검토 가능한 운영 제안이며 모든 사소한 갱신마다 승인을 요구하는 흐름을 뜻하지 않는다.

## 10. 단계별 완료 기준과 반증 조건

이 과제를 “최고 수준으로 구현했다”는 포괄적인 자기평가 대신 아래 증거로 평가한다. 잠정 출시 기준은 프로젝트가 정하는 기준이며 문헌이 보증하는 보편적 문턱이 아니다.

| 단계 | 완료에 필요한 증거 | 아직 주장할 수 없는 것 |
|---|---|---|
| 기반 구현 | 재현 가능한 원문 ID·버전·작성자·철회 전파; 의미 있는 합성 시험 통과 | 교수 철학을 파악했다 |
| 실제 자료 pilot | 실제 발언의 귀속·맥락 표본 검수; 범위와 coverage 보고; 독립 개발/검증 manifest | 전체 Drive/Gmail/Teams 파악 완료 |
| 철학 전사 pilot | B0–B3의 숨긴 비교; 교수님이 확인한 경계 사례; 작업별 오류 분석 | 모든 글쓰기·심사에서 교수님과 동등 |
| 제한 운영 | 중대한 귀속·유출·수치 변조 회귀 없음; 사람 검토 anchor와 변경 추적 | 자동 외부 발송·공식 성적/심사 결정 권한 |
| 지속 운영 | 갱신·삭제·접근 실패가 관측 가능; 버전별 성능과 퇴행 검증 | 앞으로도 무오류 |

파일럿의 필수 기능 시험에서 중대한 허위 귀속·허위 수치·범위 외 정보 노출이 한 건이라도 나오면 그 경로의 운영을 보류하고 수정한다. 관측한 0건은 실제 오류 확률 0이라는 의미가 아니다. 성능 개선은 task별로 평가하고, 한 작업의 좋아진 평균이 다른 작업의 중대한 회귀를 상쇄하지 못하게 한다.

이 권고는 다음 결과가 나오면 수정되어야 한다.

1. **B3가 B2보다 나아지지 않으면** 복잡한 원칙 추출 계층의 추가 가치를 입증하지 못한 것이다. 검색 품질을 먼저 개선하거나 카드 범위를 줄인다.
2. **말투를 가리면 선호가 사라지면** 주로 스타일 모사를 구현한 것이다. “철학 전사” 성과를 주장하지 않는다.
3. **교수님과의 일치는 높지만 사실 오류·명성 편향이 늘면** 개인화가 과제 품질을 해친 것이다. 개인 선호와 객관적 검증의 우선순위를 재설계한다.
4. **압력 아래 유지하지만 새 증거에도 유지하면** 인식적 독립성 대신 완고함을 강화한 것이다. evidence-update 시험을 개선한다.
5. **오래된 원칙이나 타인의 인용이 활성화되면** 원칙 표현 이전에 수집·귀속·시점 처리부터 수정한다.
6. **원문 수가 커져도 새 상황 적용이 좋아지지 않으면** 수집량을 성과로 관리하지 않는다. 과제 관련 증거와 반례를 더 잘 선택해야 한다.
7. **질문 응답·검수 부담이 절감되는 실제 작업 시간보다 크면** 인터뷰와 갱신 빈도를 줄이고, 영향 큰 사례에만 인간 확인을 집중한다.

가장 작은 검토 가능한 다음 구현은 기존 스타일 자산을 바꾸는 일이 아니라, 직접 발언과 후보 원칙을 분리하는 스키마, 원문·버전 기반 적용 기록, 시간·인용·압력/새 증거의 짝 시험, B0–B3 비교 입력 계약을 갖추는 것이다. 그 위에 실제 자료의 coverage와 교수님 확인된 경계 사례가 쌓여야 개인 철학 에이전트라는 주장을 검증할 수 있다.
